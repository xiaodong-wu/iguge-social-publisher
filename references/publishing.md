# 发布与核验

## 工具和身份预检

Facebook 和 LinkedIn 的身份预检、编辑文案、上传图片、预览、提交及帖子核验，
统一通过浏览器插件操作页面。使用当前安装的 Chrome 插件及其浏览器扩展连接已登录
Chrome，复用现有登录状态。Google Sheets 写入方式仍按 [记录规范](reporting.md)，
公开产品采集及本地素材脚本保持不变。

### 识别 Chrome 扩展和标签页

读取当前插件的初始化、浏览器选择和上传文档。每次新会话或断线重连都重新列举连接，按扩展类型和浏览器家族识别 Chrome。
数字连接 ID、标签页 ID 和旧会话句柄都可能变化。若当前入口提供 `cua_repl`，可在该运行时使用：

```js
const browsers = await cua.listBrowsers({ emit: false });
const chromeProfiles = browsers.filter(b => b.type === "extension" &&
  ["chrome", "google chrome"].includes((b.family || b.name || "").trim().toLowerCase()));
nodeRepl.write(chromeProfiles.map(({ id, profileName }) => ({ id, profileName })));
```

- 连接唯一时，列出该连接的标签页。成功返回空列表也表示扩展已连通，可在该配置中打开固定目标页。
  多个 Chrome 配置时，优先使用用户指定的配置，否则依据各配置中与固定目标匹配的标签页定位；仍有歧义时请用户指定配置。
  内置浏览器、MCP Apps、Edge 或 CDP 的连接均不能证明 Chrome 扩展可用。
- 优先复用本轮已绑定的目标标签。首次绑定时核对域名、路径以及 Facebook 的 `id` 或 LinkedIn 的公司 ID；
  没有合适标签才打开固定网址。保留两个平台各自的标签句柄，不操作同浏览器中其他品牌的页面或草稿。
  开页超时先重列该浏览器的标签，看目标是否已打开。页面尚在渲染时等目标控件出现，再取一次完整无障碍树（AX）或截图。
  连通后确认当前插件支持页面读写、文件上传和读取帖子链接；权限和作者另在平台界面核验。
- 扩展缺席或列标签报错时，按当前插件排障文档短暂等待并重试一次。仍失败时检查 Chrome 是否运行、对应配置的扩展是否启用、
  原生消息主机是否正常。三项正常但连接仍缺席时，按插件要求取得许可后，仅打开该配置的新窗口，再探测一次。
  仍失败则报告具体缺失项及恢复动作。沿用插件通道，不自动重启 Chrome、修复系统配置或改用独立 CDP、发布 API、Make 等方式。

### 核对目标和当前作者

在生成任何素材前，分别记录两个固定目标的实时身份和可用发布入口。允许品牌大小写和界面语言变化。

- **Facebook** 打开 `https://www.facebook.com/profile.php?id=61595573086492`，核对主页 ID 和名称。
  在目标主页上同时查看当前身份（例如“以 IGuge Healthy 的身份评论”）和可用的主页发帖入口（例如“分享新鲜事”），
  或从该入口查看编辑器作者。若当前身份是其他品牌或页面提示“切换到 IGuge Healthy”，按下节处理。
  主页标题、时间线上的历史作者和文案中的品牌名都不能单独证明发帖身份。
- **LinkedIn** 从 `https://www.linkedin.com/company/144048448/admin/dashboard/` 的公司发帖入口进入编辑器，
  核对当前公司管理路径、可编辑的正文框和作者控件中的 iGuge Healthy（例如“iGuge Healthy 发布到任何人”）。
  侧栏可能显示个人管理员，受众“任何人”也可能出现在个人编辑器；以当前编辑器的作者为准。

遇到登录、密码、MFA、CAPTCHA、需要从多个账号中挑选、权限不足或草稿归属不明时停止。

### Facebook 一次两步切换

仅在已登录且目标页面明确提供切换到该同一主页的操作时：

1. 已经是目标身份时直接核对发帖入口。需要切换时，确认当前主页 ID 和提示中的目标名称，再点击同一区域的“切换”一次。
2. 读取点击后的页面。仅当弹窗明确指向同一主页时，点击弹窗内的确认一次。控件脱离页面、快照只返回差异、
   或预期文字超时时，先读取一次完整 AX 或当前截图，依据可见的弹窗、主页或验证提示决定下一步。不要重放刚才的点击。
3. 等待页面完成切换；必要时在同一标签重新打开固定主页。重新核对当前身份和创建权限。弹窗消失不能证明切换成功。

两步合计一次序列。若仍要求切换、出现其他账号列表或验证，则停止。不重复切换，
不改用个人账号或其他管理主页。

## 最终发布前

两个平台都要先确认具备权限；全部素材通过 `validate_campaign.py` 后才开始第一条。
素材准备完毕后，在对应标签重新核对当前作者，再粘贴文案、上传图片。身份可能被同一 Chrome 配置中的其他操作切换。
如需切换，仍受本次预检至提交合计一次的限制；编辑中发生身份冲突时停止，保留本地素材。
上传时按插件文档使用绝对路径的 `social-upload.jpg`；需要 `filechooser` 时先监听，再点上传控件。导航、切换、
上传及弹窗变化后都从新快照定位控件。最终提交前核对当前编辑器或预览作者；Facebook 从已核验主页进入
`/post/create` 后可能只在预览卡片顶部显示作者，AX 遗漏时查看同一预览的截图。只看见正文中的品牌名时不能提交。
如果当前模板或上传工具不能接受本地图片，记录阻塞，不擅自发布无图帖子。

### AI 信息与可选设置

本技能发布普通商品静态图文，不把“使用过 AI”自动等同于必须手动打开每一个可选
AI 标签开关。对可选的静态图片披露保持未主动开启；若页面明确要求披露，或当前规则
要求该内容披露，则如实填写，不虚假声明“未使用 AI”或“真实拍摄”。
Meta 的规则会变化；不确定时查当前官方说明及当前发布界面。
2026-10-28 核查的 [Meta 官方说明](https://about.fb.com/news/2026/02/meta-prepares-for-2026-us-midterms/)
区分平台检测和发布者自行披露，并明确要求对逼真合成视频或音频使用披露工具。
不要把这一范围推断为所有普通商品静态图均必须手动加标，也不要据此保证静态图不会自动加标。

提交前记录 AI 选项是否出现、是否为必填、实际选择及依据；核验时若出现“AI 内容”，
打开标签说明区分“发布者添加”与平台检测。图片文件无元数据不证明不会出现平台标签。
已有帖子仅在用户要求修改且界面允许时编辑可选设置；平台强制或自动标签不能按可选开关处理。
不删除、重发或反复重编码试探识别结果。

## Facebook → LinkedIn

每个平台使用以下顺序，Facebook 先执行：

1. 复用从固定目标页打开且已重新核对的本轮编辑器，或从该目标页进入创建帖子操作。
2. 使用 `facebook.txt` 或 `linkedin.txt`，上传同一临时 JPEG。
3. 确认全部文本、图片和作者身份，核对正文不含网站链接、没有网站链接预览，处理正常的预览步骤。
4. 紧邻最终提交前运行 `update_manifest.py --status pending --submission-started`。
5. 点击最终发布按钮一次。
6. 在目标页面时间线或已发布列表找到该条帖子，打开实际帖子链接核对文本、图片和作者。
7. 保存 `evidence/facebook-public.md` 或 `evidence/linkedin-public.md`，包含核验时间、
   数字身份、观察到的作者、公开 permalink、文案/图片一致性和浏览器截图路径（可用时）。
   私有后台 URL、首页、主页 URL 和仅有“已提交”提示不算公开发布证据。
8. 记录 `published`，例如：

```bash
python3 scripts/update_manifest.py MANIFEST --channel facebook --status published \
  --url FACEBOOK_POST_URL --identity-id 61595573086492 --evidence FACEBOOK_EVIDENCE
python3 scripts/update_manifest.py MANIFEST --channel linkedin --status published \
  --url LINKEDIN_POST_URL --identity-id 144048448 --evidence LINKEDIN_EVIDENCE
```

只有点击并查看实际记录后才写核验文件；状态脚本验证路径和身份字段，不能替代观察。
平台如提供不同但真实的永久链接结构，先核实其来源，再调整本技能 URL 校验器；
不得编造一个符合正则的 URL。短链接应打开后记录真实平台永久链接。

## 结果不明与续跑

若提交后超时或浏览器断开，保留永久提交标记，记录 `blocked` 及原因。
先查看该账号的已发布内容、时间、图片和完整文案进行核对。找到则记成功；只有取得
该条未发布的明确证据后才允许一次有记录的重试。仍不明确则停止，禁止试探性再点发布。
已发布渠道不可自动删除、回滚、重发，也不能重置为 pending。

一个渠道失败或阻塞时，停止后续提交并报告当前状态。用户明确要求恢复时再重新预检；
跳过 `published` 渠道，恢复同一产品与素材。两个社媒成功但表格失败时，仅修复表格记录。
双平台均成功后可以删除上传 JPEG，原有文件哈希和审核证据保留，完成检查不再要求 JPEG。
